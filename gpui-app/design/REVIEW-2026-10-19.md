# GPUI 版 Typst 编辑器：还能改进什么

- 日期：2026-10-19
- 基线：`771b411`（`gpui-app/src/app.rs` 含未提交的便携示例路径/空态按钮改动）
- 方法：通读最近 3 个提交（`09f8dda`、`80dad2a`、`771b411`）、`gpui-app/` 与 `crates/typst-core/` 源码，并对照 gpui-kit 0.7.3 / gpui-pre 0.3.9 / typst 0.14.2 的依赖实现确认 API 语义；审查开始时工作树 `cargo check` 通过。审查为只读，未改动被审查代码。

> **审查期间工作区变化**：本地又出现了另一路未提交改动（`crates/typst-core/src/compiler.rs`、`world.rs`），把 `typst::compile` 移出了状态写锁，并加入 `DocKey`/`FileStamp` 缓存、`session` 代次、`CompileOptions::force`、`dependencies_changed()`。这正好覆盖本文 1.1 与 1.8 的一部分；若它即将合入，请以合并后的代码复核这两项，并注意 `cached_result()` 仍返回空 `diagnostics`（2.1 依然存在）。本文其余结论以 `771b411` 为准。

## 0. 总体判断

原型的功能闭环已经完整：打开项目/文件、编辑、编译、位图预览、大纲、标签页、未保存确认、PDF 导出、补全与悬停都已跑通。最近三个提交把设计审查里“看得见”的问题基本修完（重开示例标签消失、图钉阻塞 UI、过期结果覆盖、完整目录树、默认适宽、字体回退）。

下一阶段收益最高的不是继续堆拟物细节，而是三类“看不见”的问题：

1. **编译的锁设计**：一次 `typst::compile` 期间持有写锁，UI 线程每次重绘都可能被阻塞 —— 编译一次，界面就卡一次。
2. **每帧/每键的全量工作**：卡片列表、大纲、语法高亮、字数统计、预览页元素都随文档/项目规模线性增长，且大多在 UI 线程。
3. **预览位图策略**：没有像素/内存上限、没有失败兜底、页元素不做虚拟化。

另外有两个与提交说明相反的数据一致性 bug：**“不保存关闭”的覆盖回滚会被取消**、**无内容变化的复用编译会把诊断清空**。

> 本文只列改进项；`design/README.md` 中“已处理”和“已知限制”不再重复。

## 1. 优先修（P0/P1）

### 1.1 一次编译会冻结整个 UI（最影响手感）

- 证据：`crates/typst-core/src/compiler.rs:165` 取 `inner.write()`，直到函数末尾都持有写锁，`typst::compile`（`:320`）就在锁内；而 UI 线程上的重绘会读这把锁：`gpui-app/src/app.rs:1346-1354`（每张文稿卡每帧读 `pinned_entry`/`preview_entry`）、`:923`（导出）、`:476-478`（开文稿）。后台栅格化（`preview.rs:235` → `compiler.rs:466`）、补全/悬停（`lsp.rs:41`、`:95`）也排在写锁后面。
- 为什么重要：编译 0.1–3s 期间，界面重绘会在读锁上等待，表现为整窗“未响应”；快速输入时多次编译还会在全局 `COMPILE_MUTEX`（`compiler.rs:70-74`）上排队，卡顿被成倍放大。
- 建议：
  - `CompilerState` 改成“快照”模型：把 `document`、`world`、`page_sizes` 装进 `ArcSwap<Snapshot>`，编译成功后原子替换，读路径只做 Arc clone；编译串行化另用一把独立的编译 `Mutex`，不要用跨编译的 `RwLock`。
  - 编译任务用请求号（`note_compile_request`/`is_stale_request`，`compiler.rs:76-85`）在真正开始前丢弃过期请求；GPUI 目前走 `update_file_and_compile`（`:417-420`，`u64::MAX`）绕过了这套去重。
  - 渲染路径不要碰编译器：`pinned_entry`/`preview_entry` 在 `apply_compile_result` 时缓存进 app 字段。

### 1.2 “不保存关闭标签”的覆盖回滚经常不生效

- 证据：`app.rs:690`（`close_tab_now` → `revert_overlay`）→ `:709-716`（重新编译磁盘内容）→ `:695`（同一轮立即 `open_document(next)`）→ `:800`（`run_compile` 替换 `self.compile_task`，注释自述“替换任务会取消尚未开始的编译”）。除关闭最后一个标签外，回滚编译会在第一次轮询前被取消。
- 为什么重要：`CompilerState.overlays` 里仍留着用户已丢弃的文本；若被关文件是预览入口或被 import，后续编译继续使用它，预览会显示“已丢弃”的内容，与提交说明正好相反。
- 建议：回滚不要借用编译任务。新增 `CompilerState::discard_overlay(path, disk_text)`，在写锁内改 overlay/hash 并 `world.update_source_by_path`，同步调用、不触发编译；确需重编译时用独立的 `revert_task` 字段。

### 1.3 未保存确认框可以“点穿”，快捷键还会改写待处理动作

- 证据：`app.rs:2477-2489` 的 `modal` 只有背景色和绝对定位，没有 hitbox；gpui-pre 只为可交互元素插入 hitbox（`div.rs:2407-2441`），所以点遮罩空白会落到后面的卡片/编辑器。确认框靠 `dialog_focus`（`:2503`、`:2511-2517`）接收 Enter/Esc，失焦后失效。另外 `bind_keys` 是全局的（`:86-100`），对话框打开时按 Ctrl+W/Ctrl+O 仍会触发 `request()`（`:604-613`），把前一个待处理动作覆盖掉。
- 为什么重要：确认框下仍能切换文稿、移动光标甚至打字修改被询问的文档；“取消”语义不可靠。
- 建议：遮罩加 `.occlude()`（gpui-pre `div.rs:1249`）并配合 focus trap；“关于”同样处理；`pending` 存在时让全局动作提前返回；`resolve_pending` 结束后把焦点还给编辑器。

### 1.4 预览位图没有像素/内存上限，高 DPI × 高缩放会 OOM 或白页

- 证据：`preview.rs:214` 的密度是 `zoom * scale_factor`（只做 1/8 吸附），`:89` 允许 5×，`:17` 两侧各保留 2 页，`compiler.rs:461-469` 每次整页栅格化。
- 为什么重要：A4（595×842pt）在 2× 屏、5× 缩放下是 5950×8420 ≈ 5000 万像素 ≈ **200MB/页**；适宽 300% 约 72MB/页。视口 1–2 页 + 两侧各 2 页 ⇒ 常驻 5–9 页，CPU `Frame` 与 GPU 纹理各一份。页面像素超过 GPU `max_texture_dimension_2d`（常见 8192）时上传失败，整页空白且无提示。
- 建议：`pixel_per_pt` 上限（如 ≤4）并校验宽高不超过设备上限；缓存改成按字节的 LRU 预算（如 128MB）；失败时显示占位页 + “渲染失败”提示；超大页可降级用 `render_page_svg`（当前完全未用）。

### 1.5 预览页元素不虚拟化，滚轮每帧重建全部页

- 证据：`preview.rs:350-355` 每帧为全部页构建 `v_flex`/`div`/`canvas`/页码，`:364` 每个滚轮事件都 `cx.notify()`。只有位图做了“可见 ±2 页”的取舍，元素树没有。
- 为什么重要：300 页文档每次滚轮/按键重建约 1500 个元素和 300 次 canvas prepaint，滚动明显掉帧；与 1.1 的锁问题叠加更糟。
- 建议：按页高做解析偏移，只构建可见 ±1 页的元素（可顺带去掉对上一帧 `page_bounds` 的依赖）；滚轮滚动做 60–100ms 节流或在 `on_scroll` 里只在可见区间变化时 notify。

### 1.6 每次按键都在 UI 线程做 2–3 份全文拷贝 + 全语法树遍历

- 证据：`highlight.rs:67-73` 每次 `text.to_string()` + 全文比较，`:139-171` 遍历整棵语法树重建 spans；`app.rs:721-733`（`on_text_changed`）与 `:780-784`（`schedule_compile`）各做一次 `text().to_string()`，`count_chars`（`:2826`）再全扫一遍。
- 为什么重要：`Source::replace` 确实是增量重解析，但 spans 是全量重建且发生在 UI 线程；几百 KB 的文稿每键数毫秒到十几毫秒，是长文输入卡顿的主要来源。
- 建议：字数改为增量维护（或切档/保存时算）；高亮 spans 只重建受影响范围，或在超过阈值时移到后台；`schedule_compile` 复用已取到的文本。

### 1.7 光标→预览、点击→源码用的是“上次编译文本”

- 证据：`typst-core/src/ide.rs:127-136`、`:144-154` 都从 `world.source_by_path` 取源码，`jump_from_offset` 对越界 offset 只 `min(len)` 截断（`:150`）。触发点：`app.rs:882-899`（60ms 防抖）、`preview.rs:127-151`（标记后甚至会把预览滚到最后页）、`preview.rs:160`（点击反查）。
- 为什么重要：编译失败（正在输入语法错误时很常见）或 120ms 防抖窗口内，编辑器文本与编译快照不一致，标记落到末页、点击跳转偏移。
- 建议：像 `ide.rs:295-302` 的 `live_source` 一样用编辑器文本；或维护编辑器↔编译快照的前缀/后缀 diff 换算 offset；至少不要对越界 offset 静默截断后 `reveal`。

### 1.8 代次只保护 UI，后台任务仍能写回旧会话

- 证据：`app.rs:377-382` 先 `reset_session` 再取消任务；`compiler.rs:136-149` 的 reset 不在 `compile_lock` 内；generation 检查只在上屏时（`app.rs:544`、`:819`）。旧项目的编译/固定任务可能在 reset 之后写入 `preview_entry`/`pinned_preview_entry`/`overlays`。
- 为什么重要：切换项目后新项目可能用旧项目的文件当预览入口；`toggle_pin` 的旧任务甚至会把旧路径重新固定。
- 建议：`CompilerState` 加 `session_id`（reset 时自增），`open`/`pin`/编译在锁内校验；切换项目先拿 `compile_lock` 再 reset。

## 2. 正确性与一致性（P2）

1. **无内容变化时诊断被清空**：复用分支返回空 `diagnostics`/`warnings`（`compiler.rs:231-266`），`apply_compile_result` 无条件刷新（`app.rs:833-850`、`:853-877`）⇒ F5/切档后当前文件的波浪线消失。建议 `InnerState` 缓存上次诊断并随复用返回。
2. **切档丢失撤销栈/光标/滚动**：单 `EditorState` 用 `set_value` 换文本（`app.rs:459`、`:463`），该 API 会清空撤销历史、selection 归零、滚动回起点（gpui-base `input/base/state.rs:1030-1058`）。建议按文稿保存 `{cursor, scroll}` 并在切回时恢复；撤销栈需要每文稿独立 `EditorState`。
3. **保存无外部修改检测**：`on_save` 即使不脏也直接写盘（`app.rs:756-760`），打开期间的外部修改会被静默覆盖；写盘非原子（`:743`）。建议记录 `(len, mtime, hash)`，冲突时提示覆盖/重载/另存，写盘用临时文件 + rename。
4. **路径大小写/未规范化**：`workspace.rs:23-29` 只统一分隔符，不解析大小写和 `..`/`.`；`#include "Chapter.typ"` 与实际 `chapter.typ` 会产生重复标签、诊断过滤失效（`app.rs:860`）。Windows 下建议键统一小写 + canonicalize。
5. **`toggle_pin` 吞掉读盘错误**：无缓冲时 `read_to_string(...).unwrap_or_default()`（`app.rs:523-526`），读失败仍固定一个空入口。应报错并放弃。
6. **关闭最后一个标签不清预览**：`app.rs:679-707` 只清编辑器与 markers，预览仍显示旧排版（对比 `switch_project` 的 `:389-392`）。
7. **渲染失败没有兜底、失败任务每帧重试**：`app.rs:834-842` 只在成功时 `set_document`；`document` 被清空后（`compiler.rs:404-409`）`preview.rs:225-263` 会每帧重新 spawn 一个必然失败的任务，没有失败态/退避。
8. **`Jump::Url` / `Jump::Position` 被忽略**：`preview.rs:163-165` 只处理 file/offset ⇒ 点 URL 链接、交叉引用无反应；`ide.rs:184-203` 已经能返回这些类型。
9. **点击兜底 hit-test 忽略 group transform/clip**：`ide.rs:226-273` 只做坐标平移；`Jump::Position` 的二次解析在 `#rotate`/`#scale` 内容里会错位。建议对目标 page frame 直接调用 `typst_ide::jump_from_click`。
10. **主题不是唯一事实源**：`theme.rs:89` 用 `Theme::global_mut`，gpui-component 明确说明它只改字段本身，`tokens` 和 Base 投影不会重建（`theme/mod.rs:239-300`、`:460-480`）⇒ 设置过的滚动条色、分栏手柄和部分 Button token 仍是默认值。应改用 `Theme::update`。
11. **`observe(&editor)` 无条件 notify**（`app.rs:246-253`）：光标闪烁、编辑器滚动都会触发整棵 3000 行视图重建；建议删掉无条件 notify，把状态栏/页眉拆成独立订阅的子 view。
12. **卡片/大纲的每帧 O(n)~O(n²) 工作**：`render_drafts` 每帧过滤排序（`app.rs:1493-1557`），`render_card` 每卡两次锁 + 路径归一化（`:1344-1356`），大纲当前项每行 `skip(ix+1).any(...)`（`:1770-1779`）⇒ 1000 个标题约 50 万次/帧。建议倒序单次扫描求当前项、缓存 `active/pinned` 规范化字符串、列表换虚拟化组件。
13. **每帧同步 IO**：`render_sheet_header` 每帧 `fs::metadata`（`app.rs:2022-2028`）；`open_document` 同步读盘（`:448`）、`save_paths` 同步写盘（`:743`）、`toggle_pin` 同步读盘（`:525`）。读/写/stat 应放到后台并校验代次。
14. **快捷键冲突**：`Ctrl+Shift+E` 在 gpui-kit 编辑器里是“选择到行尾”，app 又把它绑定为导出（`app.rs:97`）；`Ctrl+F` 编辑器默认 `searchable=false`，既不显示查找面板也不被宿主处理。建议换一个导出快捷键，并显式处理查找。
15. **macOS 适配**：标题栏内容从 `pl_3` 开始（`app.rs:1129-1146`），会与左上角红绿灯重叠；提示文案全写 `Ctrl`，但绑定用的是 `secondary`（应为 ⌘）。
16. **无障碍与对比度**：小字色对比度不足 —— `FAINT` 2.14–2.21（`theme.rs:27`）、`WOOD_INK` 2.70、`PATH_INK` 4.0、紧凑模式行号 1.86；`paper_button` 是不可聚焦的 `div`（`skin.rs:245-276`），Tab 走不到对话框按钮，“不保存”只能鼠标；About 无 Esc 关闭（`app.rs:2581-2648`）。
17. **错误可见性**：诊断只标当前文件（`app.rs:853-878`），状态栏只显示第一条错误且无省略号/悬停/跳转（`:2408-2415`）；被 include 文件里的错误在 UI 上无处可看。
18. **扫描/空态细节**：扫描进行中会先显示“还没有 .typ 文稿”（`:385-387`、`:1538-1552`）；`scan_project` 只忽略 `target`/`node_modules`（`:72`），每次保存都全量重扫并读取所有 `.typ`（`:2895-2947`）；`.typ` 后缀大小写敏感（`:2925`）。

## 3. 功能缺口（对照 Tauri/Monaco 版与 typst-core 能力）

| 缺口 | 现状 | 建议 |
|---|---|---|
| 查找/替换 | GPUI 无；编辑器 `searchable=false` | 一行 `.searchable(true)`（`app.rs:213-223`）+ 菜单项，gpui-kit 自带面板与 Ctrl+F/Ctrl+H |
| 文件树 CRUD | 只读树（`app.rs:1560-1686`） | typst-core 下沉 fs 能力，加右键菜单（新建/重命名/删除/复制路径） |
| 诊断面板 | 只有当前文件波浪线 + 状态栏首错 | 全量列表，点击 `open_document` + `jump_to` |
| 设置持久化 | 全内存，重启丢失 | `config.json`：字体/字号/紧凑/缩放/星标/最近项目/标签 |
| 文件监听 | 无 watcher，只有 Rescan | 监听项目根；干净缓冲重载、脏缓冲提示 |
| 预览联动 | 只有光标标记 + 点击 file/offset | URL/Position、悬停、选区/未保存 diff 高亮（Monaco 版有现成实现可移植） |
| 拖拽打开 | 两版都没有 | 处理文件 drop；非文本按资源管理器打开（GPUI 已有 `TEXT_EXTS` 判定，`app.rs:74-76`） |
| 字体选择 | 启动时自动挑（`theme.rs:70-85`）；`list_system_fonts` 未用 | 设置项 + 持久化 |
| 主题 | 单一拟物亮色 | 至少补暗色变量与切换 |
| 代码折叠 | `fold_ranges` 恒空（`highlight.rs:132-134`） | 用 typst 语法节点生成折叠区间 |
| 自动补全入口 | 只有自动触发，无 Ctrl+Space | 绑定 `ShowCompletions` |
| 快速打开/全文搜索 | 只有侧栏名/标题过滤 | Ctrl+P / 项目搜索 |
| 自动保存/崩溃恢复 | 两版都没有 | 定时保存 + 会话快照 |

## 4. 工程与文档卫生

1. **`AGENTS.md` 已过期**（会影响后续 AI/新人定位）：仍写“CodeMirror 6”（`AGENTS.md:9`）与 `CodeMirrorEditor.ts`（`:44` 等），实际是 `monaco-editor ^0.52` + `frontend/src/editor/MonacoEditor.ts`；索引里的 `/mnt/f/typst-editor/...` 路径与当前 `E:\typst-editor` 不符；`:208`/`:211` 的 `syncSelectionToPreview`/`syncHoverToPreview` 已不存在。
2. **`app.rs` 3060 行**：菜单/标题栏/侧栏/标签/稿纸/预览/状态栏/对话框全在一个 impl；建议至少把 `card_frame`/`binding_strip`/纹理组合移进 `skin.rs`（`app.rs:1294-1342`），把待处理/保存决策抽成纯函数以便单测。
3. **ElementId 用索引**（`app.rs:1362`、`:1783`、`:1910`）：星标重排后 hover/tooltip 状态会错位，建议按路径做键。
